## echo -n "a" | xxd
Gibt "a" ohne Zeilenumbruch aus und zeigt den Hexwert
"a" hat den Wert 61 (hex).

## echo -n "😃" | xxd -p

Zeigt die UTF-8 Bytes des Emojis als Hex
😃 wird zu f09f9883 (4 Byte).

## echo 😃"61"

Gibt einfach Text aus
Ergebnis: 😃61

## echo -n "f09f9883" | xxd -r -p

Wandelt Hex zurück in Bytes.
f09f9883: 😃 (Hex wird wieder zum Zeichen).

## Übung (Hex Dump):
- Aufgabenstellung:
- Finde heraus wie die Ausgabe in Binär (0 und 1) mit xxd und hexdump möglich ist.

- Manchmal wird der in dem Zusammenhang (vor allem in der Netzwerktechnik) der Begriff “octet” verwendet. Was ist die Bedeutung? Gibt es einen Grund diesen Begriff zu verwenden?

- xxd unterstützt eine Option -E. Was macht diese? Ist diese heutzutage noch relevant?

- Um einen dezimalen Wert (ASCII Ziffern) als Binärwert in ein File zu schreiben können folgende Befehle verwendet werden:
```sh
$ value=65534

$ printf "%.8x" $value | xxd -r -p >data.bin
```
- Was macht das printf und der Ausdruck %.8x?
- Wie würdest du jemanden (mit einem Bash Grundverständnis) erklären wie diese Zeile die Aufgabenstellung löst.
- Finde einen Weg um den 4 Byte Binärwert aus der Datei wieder als Dezimalwert darzustellen. Hinweis: verwende od , mit Byte-Order big-endian.
- Was macht die -i Option von xxd? Was könnte eine mögliche Anwendung sein?
-----------------------

- Finde heraus wie die Ausgabe in Binär (0 und 1) mit xxd und hexdump möglich ist.
-> A: Die Ausgabe in Binär 0 und 1 mit xxd und hexdump ist mit dem Befehl xxd -b file möglich.

- Was ist die Bedeutung von octet? Gibt es einen Grund diesen Begriff zu verwenden?
-> A: Ein octet ist genau 8 Bit. Der Begriff „Byte“ war früher nicht eindeutig (konnte mehr oder weniger als 8 Bit sein). „Octet“ wird verwendet, um klarzustellen: immer 8 Bit, besonders in Netzwerken.

- Was macht die Option -E, ist diese heutzutage noch relevant?
-> A: Zeigt zusätzlich die Darstellung in EBCDIC statt ASCII und Heute kaum relevant, da EBCDIC nur noch auf alten Systemen verwendet wird.

- Was macht das printf und der Ausdruck %.8x?
-> A: %x -> wandelt Zahl in Hex um
      .8 -> immer 8 Stellen (4 Byte), mit führenden Nullen
  Beispiel:
  65534 -> 0000fffe

- Wie würdest du jemanden (mit einem Bash Grundverständnis) erklären wie diese Zeile die Aufgabenstellung löst.
-> A:
  Das macht:
1. Dezimalzahl -> Hex (printf)
2. Hex -> Binärbytes (xxd -r -p)
3. Speichern in Datei

-> Die Zahl wird als 4-Byte Binärwert gespeichert.

- Finde einen Weg um den 4 Byte Binärwert aus der Datei wieder als Dezimalwert darzustellen. Hinweis: verwende od , mit Byte-Order big-endian.
-> A:
  ```sh
  od -An -t u4 --endian=big data.bin
  ```
    -t u4 -> 4 Byte als unsigned Zahl
    --endian=big -> richtige Byte-Reihenfolge

  -> Gibt wieder 65534 aus.

  -  Was macht die -i Option von xxd? Was könnte eine mögliche Anwendung sein?
-> A: Erzeugt ein C-Array aus den Binärdaten.
- Beispiel:
```sh
unsigned char data[] = { 0x00, 0x00, 0xff, 0xfe };
```
-> Binärdaten direkt in C-Programme einbauen.

Erstelle mit dem Windows Editor eine Textdatei (soll auch die Zeichen äüöÄÜÖß€ enthalten) speichere einmal in UTF-8 und einmal in ANSI Kodierung. Importiere diese 2 Textdateien in ein REPL (Achtung: nicht im REPL Editor öffnen, dieser kann die Dateien verfälschen).

- Zeige mit cat den Inhalt beider Files an. Welcher Unterschied ist feststellbar? Was wird die Standard Kodierung der REPL Kommandozeile sein?
- Analysiere den Inhalt beider Files per Hexdump: wie werden in beiden Varianten die Buchstaben Ö, ß und € kodiert?
- Wie werden Zeilenumbrüchen in den unter Windows erstellten Dateien dargestellt? Wie sieht das in einer Datei aus die unter Linux (z.B. REPL) erstellt wurde?
- Konvertiere in der Kommandozeile (mit iconv) ANSI (auch code page 1252 genannt, kurz: CP-1252) nach utf-8 und prüfe das Ergebnis.
- Forschung/Recherche: Was ist der Unterschied zwischen ANSI und Latin-1?

----------------------------------------------------

- Zeige mit cat den Inhalt beider Files an. Welcher Unterschied ist feststellbar? Was wird die Standard Kodierung der REPL Kommandozeile sein?
-> A:
  cat utf8.txt -> Zeigt den Text korrekt an:
  ```sh
  äüöÄÜÖß€
  ```
  cat ansi.txt -> Zeigt falsche Zeichen an wie viele andere Symbole
  
-> STandartkodierung ist UTF-8.

- Analysiere den Inhalt beider Files per Hexdump: wie werden in beiden Varianten die Buchstaben Ö, ß und € kodiert?
-> A:
  xxd utf8.txt

  Beispiel:
  ```sh
  c3 a4   → ä
  c3 b6   → ö
  c3 9f   → ß
  e2 82 ac → €
  ```
 xxd ansi.txt

Beispiel:
```sh
e4 → ä
f6 → ö
df → ß
80 → €
```
Ö in UTF-8 -> c3 96 und in ANSI -> d6
ß in UTF-8 -> c3 9f und in ANSI -> df
€ in UTF-8 -> e2 82 ac und in ANSI -> 80

- Wie werden Zeilenumbrüchen in den unter Windows erstellten Dateien dargestellt? Wie sieht das in einer Datei aus die unter Linux (z.B. REPL) erstellt wurde?
-> A:
   Windows Datei:
  ```sh
  0d 0a   → CR LF
  ```
Linux / REPL Datei:
```sh
0a      → LF
```
-> Der Unterschied ist im Hexdump sichtbar.

- Konvertiere in der Kommandozeile (mit iconv) ANSI (auch code page 1252 genannt, kurz: CP-1252) nach utf-8 und prüfe das Ergebnis.
-> A:
  ```sh
  iconv -f CP1252 -t UTF-8 ansi.txt > fixed.txt
  ``` 
-> Wandelt ANSI -> UTF-8

cat fixed.txt

Zeigt wieder:
```sh
äüöÄÜÖß€
```
- Forschung/Recherche: Was ist der Unterschied zwischen ANSI und Latin-1?
-> A:     ANSI hat zusätzliche Zeichen (z.B. €)
          Latin-1 hat kein €

## Challenge (JPEG/Exif):

Bilddateien (wie JPEG) enthalten häufig Zusatzinformationen (Bezeichnung der Kamera, Verwendete Blende, Geo-Position, …) im sogenannten Exif Format. Versuche anhand eines Bildes (z.B. selbst mit der Handykamera gemacht) die Struktur der Exif Daten zu verstehen.

-> A: 
EXIF sind Metadaten, die in JPEG-Bildern gespeichert werden
Sie enthalten z.B:
- Kamera-Modell
- Datum/Uhrzeit
- ISO / Blende
- GPS-Daten
-----------------------
- exiftool bild.jpg

-> Zeigt alle EXIF-Daten übersichtlich an.
- Beispiel:
```sh
Camera Model Name : iPhone
ISO               : 100
Date/Time         : 2024:05:10 12:30:00
```
---------------------
- xxd bild.jpg

-> Zeigt die Datei im Hexdump.

Man erkennt:
- JPEG Header
- EXIF Bereich

----------------------
- Eine JPEG-Datei besteht aus:

1. Header (ff d8)
2. APP1 Segment (EXIF)
3. TIFF Struktur
4. Tags (Informationen)

----------------------
- Beispiel für EXIF Tags sind:

- Kamera: iPhone
- ISO: 100
- Belichtungszeit
- GPS Koordinaten
